# ARKNOZ PROJECT DATA STANDARD V1

Status: FROZEN BASELINE
Purpose: Universal research and ingestion standard for Arknoz Projects.
Scope: Buildings, infrastructure, landscape, interiors, bridges, transport,
healthcare, education, cultural, commercial, residential, industrial,
heritage and other Built World projects.

---

## 1. PRINCIPLE

Arknoz does not win by showing the largest number of fields.

Arknoz wins by showing:

RELEVANT INFORMATION
+ VERIFIED INFORMATION
+ CONNECTED INFORMATION
+ TRACEABLE SOURCES
+ USEFUL TECHNICAL UNDERSTANDING

Missing information is acceptable.

Unsupported information is not acceptable.

Do not create content merely to fill a page.

---

## 2. UNIVERSAL PROJECT MASTER

Every project record feeds the same six Project Master areas:

01 Overview
02 Media
03 Drawings
04 Project Detail
05 Connected World
06 Evidence & Analysis

Sections and fields appear only when genuine supported data exists.

---

## 3. LEVEL A — REQUIRED PROJECT IDENTITY

A project candidate should attempt to establish:

- Project title
- Canonical slug
- Project parent / project type
- Geography label
- Geography slug where available
- City / region / country where relevant
- Project status where verifiable
- Intended content status
- Verification status
- Source set
- Provenance

A public project must never rely on an unsupported title, location or project type.

---

## 4. LEVEL B — CORE PROFESSIONAL FACTS

Research these for every project.

Display only when supported.

### Identity and programme

- Project type / typology
- Status
- Location
- Design year
- Construction start
- Completion
- Opening / inauguration
- Renovation / restoration dates
- Heritage inscription where applicable

### People and organisations

- Architect / design lead
- Client / owner
- Developer
- Executive architect
- Structural engineer
- Civil engineer
- Building services / MEP engineer
- Landscape architect
- Interior designer / interior architect
- Main contractor
- Project manager
- Cost consultant / quantity surveyor
- Specialist consultants
- Photographer

No fixed number of participants.

Use only genuine roles supported by evidence.

### Scale

Research the most meaningful measure for that project.

Examples:

- Gross floor area
- Site area
- Height
- Floors
- Units
- Capacity
- Seats
- Beds
- Length
- Span
- Stations
- Track / route length
- Bridge deck area
- Landscape area

Do not force irrelevant scale fields.

---

## 5. LEVEL C — DESIGN, ENGINEERING AND CONSTRUCTION

Research where meaningful:

- Design concept
- Structural system
- Foundation system
- Primary construction method
- Envelope / facade system
- Roof system
- Primary materials
- Significant secondary materials
- Environmental / climatic strategy
- Building services strategy
- Prefabrication / modular systems
- Digital fabrication where relevant
- Construction innovation
- Heritage / conservation strategy
- Retrofit strategy
- Landscape strategy
- Public realm strategy

Arknoz should explain HOW the project works.

Do not create generic descriptions such as
"uses sustainable materials" without source support.

---

## 6. MATERIALS AND PRODUCTS

Structured material information may include:

- Concrete
- Steel
- Timber
- Masonry
- Glass
- Ceramic
- Stone
- Aluminium
- Composite materials
- Earth / rammed earth
- Recycled / reused material
- Bio-based material
- Other significant materials

Manufacturer / product information is OPTIONAL.

Include products only when:

1. the product is genuinely documented,
2. it materially contributes to understanding the project,
3. manufacturer identity is reliable,
4. it is not merely promotional tagging.

Do not turn a project record into an advertising catalogue.

---

## 7. PROJECT STORY

Where sufficient source material exists, generate:

### Project understanding

A concise source-grounded explanation of:

- what the project is,
- why it matters,
- its design or engineering significance,
- its relationship to context,
- the most important challenge or innovation.

### Visual statement

One short sentence capturing the project's defining quality.

Do not manufacture significance.

If evidence is weak, keep this section factual and short.

---

## 8. TIMELINE

Timeline entries must represent meaningful project events.

Possible milestones:

- Competition announced
- Design selected
- Design started
- Planning approval
- Construction started
- Major engineering milestone
- Topping out
- Completion
- Opening
- Heritage inscription
- Renovation
- Expansion
- Restoration
- Demolition where historically relevant

Avoid trivial events.

Avoid duplicating the same date under multiple names.

---

## 9. MEDIA

Media classes:

- Hero
- Project photography
- Context photography
- Interior photography
- Detail photography
- Construction photography
- Historic photography
- Aerial / site photography

Every media asset must retain:

- source
- attribution
- rights / licence status
- provenance status
- entity association

No rights-safe evidence = do not publish the image.

---

## 10. DRAWINGS AND TECHNICAL MATERIAL

Possible material:

- Site plan
- Floor plan
- Section
- Elevation
- Structural diagram
- Engineering diagram
- Detail
- Axonometric
- Exploded diagram

- Historic drawing

Drawings should be used because they explain the project.

## 11. TYPE-SPECIFIC DATA

The project type determines additional research.

### Tall buildings

Seek:

- Height
- Floors
- Structural system
- Core system
- Facade system
- Vertical transport
- Floorplate
- Mixed-use programme where applicable

### Bridges

Seek:

- Bridge type
- Total length
- Main span
- Width
- Structural material
- Deck system
- Foundation / pier system
- Designer / engineer
- Capacity / transport role

### Transport infrastructure

Seek:

- Infrastructure type
- Route length
- Stations
- Capacity
- Alignment
- Structural / civil system
- Operator / client
- Delivery team

### Hospitals

Seek:

- Bed capacity
- Clinical programme
- Gross area
- Healthcare planning strategy
- Specialist systems
- Client / operator

### Stadiums / arenas

Seek:

- Capacity
- Roof system
- Bowl / seating strategy
- Span
- Event programme
- Crowd / circulation strategy

### Housing

Seek:

- Number of units
- Housing type
- Density
- Unit mix where meaningful
- Site area
- Shared / public space strategy

### Landscape / public realm

Seek:

- Site area
- Landscape typology
- Ecology
- Water strategy
- Planting strategy
- Public programme
- Existing-site transformation

### Interiors

Seek:

- Interior area
- Programme
- Interior architect / designer
- Primary materials
- Furniture / joinery where significant
- Lighting strategy
- Existing-building relationship

### Heritage / restoration

Seek:

- Original date
- Heritage status
- Conservation architect
- Restoration period
- Intervention strategy
- Original fabric retained
- New interventions
- Heritage authority where relevant

Other project types may introduce their own meaningful technical fields.

The master schema must remain extensible.

---

## 12. CONNECTED WORLD

Create connections only when Arknoz has real evidence.

Possible connections:

- People
- Organisations
- Products
- Materials
- Knowledge
- Places
- Universities
- Related projects
- Methods
- Technologies

No inferred relationship should appear as a confirmed connection.

---

## 13. RELATED READING

Use a small number of high-value references.

Prefer:

1. official project / institution source
2. architect / engineer source
3. government / heritage / academic source
4. respected professional publication
5. strong independent technical source

Avoid weak SEO pages, copied articles and repetitive coverage.

Related Reading is for understanding.

Provenance is for evidence.

They are not the same function.

---

## 14. PROVENANCE

Every material project fact should be traceable to supporting evidence.

Record:

- Source label
- Organisation
- URL
- Source type
- Independent / first-party status where available
- Fact association where supported
- Verification status

Conflicting sources must not be silently reconciled.

Keep the conflict visible for review.

---

## 15. SOURCE PRIORITY

Preferred evidence order:

A — primary / official documentation

Examples:
project owner,
architect,
engineer,
government,
heritage authority,
institutional archive,
official planning documentation.

B — specialist professional / academic source

Examples:
technical journals,
universities,
peer-reviewed material,
professional institutes,
museum/archive sources.

C — respected architecture / construction publication

Use for supporting context and discovery.

D — secondary web source

Use cautiously.

E — unverified aggregation / promotional / copied source

Do not use as sole support for important claims.

---

## 16. RELEVANCE FILTER

A fact belongs on Arknoz only if it helps answer at least one question:

- What is this project?
- Who created or delivered it?
- Where is it?
- When did it happen?
- Why is it significant?
- How was it designed?
- How was it engineered?
- How was it constructed?
- What materials or systems matter?
- How did it evolve?
- What does it connect to?
- What evidence supports the claim?

If it answers none of these, exclude it.

---

## 17. ANTI-JUNK RULES

Do not publish:

- duplicate facts
- duplicate descriptions
- generic promotional copy
- unsupported superlatives
- meaningless keyword lists
- SEO filler
- arbitrary social metrics
- irrelevant awards
- unrelated products
- excessive manufacturer lists
- weak related-project recommendations
- speculative people / organisation relationships
- unsupported sustainability claims
- empty sections

---

## 18. PROJECT QUALITY TARGET

A strong Arknoz project should ideally contain:

- clear identity
- meaningful location
- key project dates
- principal designer
- useful professional credits
- meaningful scale
- concise project understanding
- technically useful design / engineering information
- several relevant visual assets where rights allow
- technical drawing material where available
- meaningful timeline
- reliable source set
- evidence-backed connections

Not every project will contain every element.

Completeness must never override truth.

---

## 19. PUBLICATION PRINCIPLE

Candidate
→ researched
→ source-backed
→ reviewed
→ publishable

Publication must fail closed when critical evidence,
provenance or media rights are unresolved.

---

## 20. ARKNOZ DIFFERENTIATOR

The target is not:

"more information than competitors."

The target is:

"more useful understanding per screen."

Arknoz Project Master should combine:

professional project facts
+ visual understanding
+ drawings
+ engineering / construction knowledge
+ project evolution
+ Built World connections
+ transparent provenance
+ deeper Arknoz analysis.

That is the Arknoz Project Standard.
